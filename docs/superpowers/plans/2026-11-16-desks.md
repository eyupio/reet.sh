# Desks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Desks tab in reet: saved sets of terminal tabs, each tab split into panes that are ordinary sessions, with names, colours, layouts, live folder, per-pane command history and reopen after a reboot.

**Architecture:** One versioned JSON document per desk on the controller (`desks` table), validated by a pure Go package with a TypeScript twin. The browser draws the split tree and attaches each visible pane through the existing terminal attachment. One new machine feature, `desk-shell-v1`, reports each session's live folder and starts desk shells through a wrapper that gives each pane its own history file.

**Tech Stack:** Go (net/http, modernc SQLite), tmux on machines, Svelte 5 + TypeScript, xterm 6, `node:test`, Playwright scripts. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-16-desks-design.md` (read it first; the mock-ups in `docs/design/desks/index.html` are the look).

## Global Constraints

- Limits: 50 desks an account, 20 tabs a desk, 9 panes a tab, names at most 80 characters, start-up command at most 2000, `doc` at most 64 KiB, split ratio 0.1 to 0.9, minimum pane 20×8 cells.
- Session limits become 24 live a machine and 64 an account (from 8 and 32).
- Colours only from `web/src/lib/projectColour.ts`: `'' | red | amber | green | blue | violet`.
- `schema` is 1. A desk with a higher schema is neither shown nor overwritten.
- A session id appears in at most one pane across an account's desks.
- Nothing of a desk in localStorage except the last opened desk id (`reet.desks.last.<uid>`). No history or output on the controller or in the browser.
- Opening a desk never creates a shell. A start-up command is never run without a press.
- Routes: accounts, cookie, same origin (the `terminalAccess` rule); every write takes `expect` and answers 409 with the current record when stale.
- Old peers: no new field or message reaches a machine or controller that did not negotiate `desk-shell-v1`.
- Copy: British spelling, familiar labels, plain destructive confirmations (`docs/voice-and-copy.md`). Every touch target at least 44 px on touch.
- Each commit builds: `npm --prefix web run check`, `npm --prefix web run build`, then `go vet ./...` and `go test -race ./...`. A new `.test.mjs` is added to the `test` script in `web/package.json`.
- Never `kill-server` a shared tmux; tests use the private socket the real-PTY workflow makes.
- Read `handoff.md`'s code map before adding a type; `TerminalSession` exists.

## Review Focus

1. Two windows edit one desk at once: the later write must not drop the earlier one's tab or pane (Task 6 test `merges a rename onto a newer doc`; Task 3 test `TestDeskStaleWriteReturnsCurrent`).
2. A pane's folder with spaces, quotes, a newline or non-UTF-8 bytes: the sweep must not fail and the reopen must land in that exact folder or say why not (Task 9 `TestLiveDirSkipsNewlinePath`, `TestLiveDirKeepsSpacesAndQuotes`).
3. The person's rc file sets `HISTFILE` or `PROMPT_COMMAND` itself, or exits non-zero: the pane still gets its own history and the shell still starts (Task 11 `TestBashWrapperSurvivesRcThatOverridesHistfile`, `TestWrapperSurvivesFailingRc`).
4. A session ended, archived or taken over elsewhere while a desk shows it, or a machine forgotten: the pane changes state, the doc never names a session that is gone, and Type in all panes turns off (Task 4 `TestForgetMachineClearsDeskPanes`; Task 13 e2e `type in all stops when a pane drops`).
5. A doc at the edges: 9 panes then a split, a ratio of 0 or NaN, a leaf naming a missing pane, a pane in the tree twice, an unknown colour, a 65 KiB doc (Task 1 table tests name each).
