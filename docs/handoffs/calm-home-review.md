# Home projects layout and workspace review

## Review

Home should provide the same direct hierarchy as the session workspace: identify the page, choose work, start a session, and reach supporting details. Reviewing the merged #640 desktop and phone views exposed these issues:

| Finding | Implemented change |
| --- | --- |
| The persistent projects column consumes roughly 301 px beside the global navigation | A 56 px strip by default, a visible Projects control to expand it, and respect for an explicitly saved expanded choice |
| Large greeting, host eyebrow and explanatory text push work down the page | Compact Home title, a short description and machine/attention counts |
| Board and Continue views each provide another heading and primary start control | One New session button in the Home header; the board keeps its accessible region name |
| Routine running rows have status fills, accent bars and bordered pills | Quiet grouped rows; state words and provenance remain, with edge emphasis for waiting/failure |
| Continue rows require a context menu to reach actions | Visible 44 px actions button per row, using the existing session menu and focus return |
| Project cards and nested board surfaces compete with the work | Flat unselected project rows and quieter board surfaces; selected projects, drop targets and status text remain distinct |
| Attention summaries repeat their heading and surround each item with another card | One visible Needs you summary and inline items; approvals, questions, failures and Mark seen keep their existing behavior |

## Contracts

The projects rail uses 56 px when no expanded choice is saved, returning about 245 px to the work area at the default rail width. Expanding it keeps the existing resize, grouping and management controls. An explicitly saved expanded/collapsed choice is preserved; merely loading Home writes no preference.

Planning board remains the initial default and the saved Home choice remains authoritative. Board view/sort/density and in-memory state are preserved. The board stays mounted when Continue is selected. No routes, API contracts, agent lifecycle or permissions change. New session opens the existing Start an agent dialog; there is no launch on view selection or page load.

Project selection, grouping, reordering, drag-and-drop, worktrees, backlog capture, images, refine/start, filters, session recovery and machine workflows remain available. Attention retains exact permission ownership, truncation refusals and the existing Allow once/Deny endpoints. The quiet attention style applies only to Home; the bell and other attention surfaces keep their contracts.
