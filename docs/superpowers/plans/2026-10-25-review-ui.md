# Review UI for pins, checks and ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the signed-in owner pin a library revision to a machine scope, check what the machine holds, and adopt or release ownership, from a dialog on the Machines page.

**Architecture:** One read-only server endpoint supplies a metadata-only file breakdown for adoption. In the browser, a pure `contentReview.ts` holds every label, state and decision rule; a `MachineSkillContent.svelte` dialog shell owns data, polling and confirmations and renders three small step components. Nothing is written to any machine.

**Tech Stack:** Go 1.27.1 (stdlib, pure-Go SQLite), Svelte 5 + TypeScript (runes), Node 22 `node:test`, Playwright fixtures with synthetic API responses.

**Spec:** [docs/superpowers/specs/2026-10-25-review-ui-design.md](../specs/2026-10-25-review-ui-design.md). It is the authority; where this plan is silent, the spec decides.

## Global Constraints

- Go 1.27.1, Node 22, Svelte 5 runes, no new dependency (not even a dev one). No competing product named anywhere.
- Build the frontend before Go checks: `(cd web && npm run check && npm run build)` with 0 errors and 0 warnings, then `go vet ./...`, `go test -race ./...` with tmux on `PATH`, `(cd mcp && npm ci && npm test)`, `git diff --check`.
- Never call `GET /api/v2/skill-bundles/{bundle}/revisions/{revision}` (it returns file bytes). Never store pin, check or ownership data in `localStorage`, `sessionStorage` or IndexedDB; request keys live in memory.
- The word "verified" never describes an ownership record. The ownership sentence is exactly: **Recorded by reet from a recent check, not verified on the machine.** (The word appears only to deny it.) The change notice is exactly: **Applying changes isn't available yet.** The fallback is exactly: **Something changed. Check again.**
- Presence reads `present` = **Found**, `absent` = **Not there yet**, `unknown` = **Couldn't tell**.
- At most one light Yorkshire phrase per heading, lede or success message ([voice guide](../../voice-and-copy.md)); confirmations, errors and state labels stay plain. British spelling.
- Accounts mode only, hidden for legacy auth, read-only for viewers. Dialog is a native `<dialog>`; no horizontal page scroll at 320, 375, 768 and 1440px, light and dark.
- Existing tests keep their expectations. Terminal sessions and controls and the deferred security/PIN preference are untouched.
- Browser fixtures run here with `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium` against `npm --prefix web run preview -- --host 127.0.0.1 --port 4173`.

## Review Focus

Failure modes the spec implies that a first reading of the tasks would miss, most likely first; each is pinned by a test in the owning task.

1. A check that went stale, was superseded or lost its pin is still on screen when the person reaches Adopt. Adopt must be enabled only by the latest server read saying `captured` and not stale, and the confirmation re-reads first. (Tasks 2, 5)
2. A state, reason or planner code the tables have never seen (a newer server) must read the fallback and never enable Adopt. (Task 2)
3. A damaged ownership record (`damaged: true`, empty provenance and evidence) is listed with Release only, shows no claims, and cannot crash a render that expects evidence. (Task 5)
4. Odd content in the file tables: 256 files, very long or unicode paths, and a path present on both sides with different bytes (shown as one row). The table scrolls inside its container; the page does not. (Tasks 2, 5, 6)
5. Double activation and lost replies: a second click on Check or Record ownership sends nothing new, an uncertain create is retried with the same key and reconciled through GET, and every pin write carries the current version. (Tasks 3, 4, 5)

### Task 2: Client API, types and the pure review logic

**Files:**
- Modify: `web/src/lib/api.ts` (types and thin wrappers), `web/package.json` (append `&& node src/lib/contentReview.test.mjs` to `test`)
- Create: `web/src/lib/contentReview.ts`, `web/src/lib/contentReview.test.mjs` (transpile `contentReview.ts` the way `events.test.mjs` does)

**Interfaces:**
- Consumes: the JSON shapes in `internal/store` (`SkillContentTarget`, `SkillContentPreview`, `SkillContentReceipt`, `AdoptionCandidate`, `AdoptionFile`) and `internal/skillplan` (`Plan`, `Action`, `Conflict`, `Preserved`), `internal/skillpreview.Capture`; existing `PrivateBundle`, `PrivateRevision`, `SyncEnvironment`, `SyncAgent`.
- Produces in `api.ts` (types mirror the Go JSON exactly; `inventoryRevision` is a string): `ContentPin`, `ContentPinWrite`, `ContentPreview`, `ContentCapture`, `ContentPlan`, `AdoptionOffer`, `AdoptionBreakdown`, `ContentReceipt`; wrappers `getContentPins(signal?)`, `saveContentPin(input)`, `removeContentPin(id, expectedVersion)`, `getContentPreviews(signal?)`, `getContentPreview(id, signal?)`, `requestContentPreview(input)`, `stopContentPreview(id)`, `dismissContentPreview(id)`, `getContentReceipts(signal?)`, `adoptContent(input)`, `releaseContentReceipt(id, expectedVersion)`, `getAdoptionBreakdown(previewId, revisionId, signal?)`. Wrappers hold no logic and never call the revision-bytes read.
- Produces in `contentReview.ts` (all pure, no DOM, no fetch):
  - `scopeEligibility(env: SyncEnvironment, agents: SyncAgent[] | undefined, opts: { accounts: boolean; canWrite: boolean; now: number }): { ok: true } | { ok: false; reason: string }`: not accounts or not a writer; agent not in `agents|claude|cursor|opencode`; a project scope whose agent is not `claude` or `agents` or whose path is not absolute; no complete scan within 14 days; no enrolled agent for the host (case-insensitive) or one that is paused. Each failure has its own plain reason.
  - `presenceLabel(p)`, `ownershipNote(rootOwnership)` (`''` for exclusive), `OWNERSHIP_SENTENCE`, `APPLY_NOTICE`, `FALLBACK`; `checkStateLabel(state)`, `reasonText(code)`, `failureText(code)`, `planCodeText(code)`, `preservedText(reason)` (closed tables below; unknown input returns `FALLBACK`).
  - `classifyCheck(p: ContentPreview | null, readAt: number, now: number): { kind: 'none' | 'working' | 'current' | 'refreshing' | 'stale' | 'blocked' | 'ended'; headline: string; reasons: string[]; canAdopt: boolean; canCheckAgain: boolean }`: `readAt` is the browser time the response arrived, so the browser's clock is never compared with the server's. The server's `stale` state and reasons are the authority on freshness. `canAdopt` is true only for `kind: 'current'`: state `captured`, no reasons, `adoptable(p)` below, and `readAt` and `now` both finite with `now >= readAt` and `now - readAt` within 30 seconds (the shell passes a fresh `Date.now()` at the moment it asks, not a cached timer tick). A captured read older than that, from the future, or with a time that is not a number is `refreshing` (not adoptable until the shell has read it again).
  - `adoptable(p): boolean` (present, exclusive, complete manifest, exactly one conflict `adoption_required`, non-empty `reviewHash`), `summarisePlan(plan?): { kind: 'up_to_date' | 'changes' | 'conflicts' | 'adoption' | 'unknown'; actions: ContentPlan['actions']; conflicts: …; preserved: … }`.
  - `candidatesFor(offer?): AdoptionOffer['candidates']` (as given, server order) and `preselect(offer?): string` (the revision ID only when exactly one candidate, else `''`).
  - `groupBreakdown(b): { path: string; state: 'claimed' | 'stays_yours' | 'library_only' | 'differs'; bytes: number; executable: boolean; digest: string }[]` (a `stays_yours` and a `library_only` row on one path become one `differs` row), `claimSummary(b)`.
  - `pollDelay(state: string, hidden: boolean): number | null` (3000 for `queued` and `capturing`, 10000 for `captured` so the server's `stale` or `superseded` verdict reaches an open Adopt step within seconds, `null` for every other state and whenever the tab is hidden).
  - `describeError(e: unknown): string` (server `error` text when present, else a generic sentence; never raw stack text).
- Closed code tables, copied from the Go side; the test enumerates them so a new server code fails loudly here: states `queued capturing captured failed cancelled expired superseded stale`; fence reasons `pin_changed pin_removed connector_paused connector_removed process_changed inventory_changed scope_removed receipt_changed expired stale`; failure codes `capture_failed scope_unavailable plan_unavailable`; planner codes `adapter_unsupported root_shared root_unknown generation_changed inventory_changed observation_unknown observation_stale observation_invalid adoption_required unmanaged_path managed_target_missing local_modified both_modified local_deleted result_invalid baseline_target_mismatch baseline_bundle_mismatch`; preserved reasons `local_only additive_managed`.

- [ ] **Step 1: Write the failing node tests** with the spec's exact values: every table row maps to a non-fallback sentence and an unknown string returns `FALLBACK`; the three exact constants; `scopeEligibility` for each failure and the passing case, including host case-insensitivity and a 14-day boundary; `classifyCheck` for no check, queued/capturing (working, `canAdopt` false), captured and just read (current), captured whose read is over 30 seconds old (refreshing, `canAdopt` false), the server's `stale` state, superseded with reasons, expired, failed, cancelled, an unknown state (blocked with `FALLBACK`, `canAdopt` false) and a captured check that is not adoptable; `summarisePlan` for ready-no-actions, ready-with-actions, conflicts, adoption-required and a missing plan; `preselect` for zero, one and two candidates; `groupBreakdown` merging a pair and keeping order; 256-file input; `pollDelay` for each state (3000, 10000, null) and hidden; `describeError`.
- [ ] **Step 2: Run** `node web/src/lib/contentReview.test.mjs`. Expected: FAIL (module missing).
