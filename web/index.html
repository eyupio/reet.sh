What reet.sh does

Command

Open a terminal on any machine, start an agent in a folder, and pick the session up again later.

Sync

Send a skill or setup to one machine or the whole fleet. You review the exact plan before anything changes.

Back up

Setups and skills are kept on the controller, sealed and verified, so a machine can be put back as it was.

Start fresh

Enrol an empty machine and it picks up your skills and setups. It ends up like the rest.

How reet.sh works

Enrol a machine with one command.

Run the agent on a laptop, a VPS or a lab box. It dials out to your controller, so there is no port to open, and reports in with the agents, skills and setups it already has.

Command your agents from one place.

Open a terminal on any enrolled machine, start an agent in a folder, keep sessions running and pick them up later.

Sync and restore.

Push a skill or setup to one machine or all of them, review the plan first, and restore a setup on a machine that has nothing.

The workspace around your agents

Your fleet, in view.

Every enrolled machine in one control room: what it has installed, whether it is in sync, and the work already running there.

Setups worth keeping.

Save and share named AI setup profiles through reet. Pull a known setup when preparing another machine, with restore and verification in the CLI.

Skills that travel.

Keep a central skill library, bring machine discoveries back, and choose a source and destinations for distribution.

Sync, on your terms.

Choose one machine or the fleet. Review exact plans and resolve conflicts before applying changes. A machine applies a plan sent from here only when its owner has opted in on that machine.

Your infrastructure. Your call.
